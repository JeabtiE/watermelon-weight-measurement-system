# Watermelon Size & Weight Measurement System

A system that measures the size of a watermelon and estimates its weight using a webcam combined with OpenCV for image processing and Qt for the graphical user interface (GUI).

## Overview

The program uses a camera to capture an image of a watermelon, then processes the image to:

1. Find the contour of the watermelon in the frame
2. Measure width/height in pixels and convert to centimeters using a `pixel_per_cm` ratio
3. Estimate weight with an empirical ellipsoid-approximation formula
4. Classify quality into grade A / B / C based on weight
5. (In some versions) Save results to a SQLite database for historical summaries and export

## Project Structure (what each folder is)

This project was developed through several versions/modules, each tried out separately. Each folder represents one stage of development:

| Folder | Description | Highlights |
| --- | --- | --- |
| `compro/` | Console prototype (no GUI) | The very first test of the size/weight measurement algorithm, using a fixed `pixel_per_cm` (25.5) |
| `GUI/` | First Qt Widgets app with a screen | Has a Home page, MainWindow (actual measurement), and CalibrationWindow (scale adjustment) |
| `GUI_ArUco/` | Qt app similar to `GUI/` | Uses an ArUco marker to compute homography for camera angle/scale correction instead of a fixed constant |
| `GUI_calibrate/` | Qt app starting at the CalibrationWindow | Automatically calibrates scale (`pixel_per_cm`) using a **card (national ID card/credit card, standard size 8.56 cm)** as a reference object instead of a fixed constant or ArUco marker |
| `GUI_card/` | Qt app starting at CalibrationWindow → MainWindow | Version that adds A/B/C grading and saves results to SQLite (`watermelon.db`) |

The `opencv/` folder found in some archives **is not part of this project's code** — it is a full copy of the OpenCV source that was built locally (because `CMakeLists.txt` references `OpenCV_DIR` as a hardcoded path, `C:/project_compro/opencv/build`). The `build/`, `.qtcreator/`, and `.vscode/` folders are auto-generated by the IDE/CMake and should not be committed.

## Pipeline

All versions follow the same overall concept, differing mainly in scale calibration and additional features:

1. **Capture**: Open the camera with `cv::VideoCapture(0, cv::CAP_DSHOW)` (forces the DirectShow backend on Windows to avoid camera-open failures/crashes)

2. **Preprocessing**: Convert to grayscale → `GaussianBlur` to reduce noise → detect edges/segment the background with `adaptiveThreshold` (console/GUI versions) or `Canny` (calibrate version) → `morphologyEx` (`MORPH_CLOSE`) to close gaps so the contour is complete

3. **Find contour**: `findContours`, then filter by a minimum area threshold; later versions also check circularity (`circularity = 4πA/P²`) to select round/oval watermelon-like shapes rather than angular objects

4. **Measure size**: Use `minAreaRect` on the largest contour to get width/height in pixels, then stabilize the value with an exponential moving average (`avg = 0.9*avg + 0.1*new`)

5. **Unit conversion**: Pixels → centimeters by dividing by the calibrated `pixel_per_cm`

6. **Estimate weight**: Use an empirical ellipsoid-approximation formula:

   ```
   weight(kg) = 0.0019 * (2 * width_cm * height_cm^2 * π / 3) + 0.2228
   ```

7. **Grading** (`GUI_card` only):
   - Weight > 3.0 kg → Grade A
   - Weight 2.0–3.0 kg → Grade B
   - Weight < 2.0 kg → Grade C

8. **Save results** (`GUI_card` only): Write to the SQLite table `watermelon(id, width, height, weight, grade, timestamp)`, with a per-grade count summary and export support

## Scale Calibration — 3 approaches that were tried

| Method | Located in | Principle |
| --- | --- | --- |
| Fixed constant | `compro/`, `GUI/` | Sets `pixel_per_cm = 25.5` as a fixed value (assumed to be measured at a fixed camera-to-object distance of 60 cm, based on the on-screen message "*** Keep 60 cm distance ***") |
| ArUco marker | `GUI_ArUco/` | Uses a marker to compute homography and correct the camera viewing angle (the detailed scale-computation logic in this version has not been fully verified) |
| Standard card detection | `GUI_calibrate/`, `GUI_card/` | Finds a quadrilateral contour (`approxPolyDP` yields 4 corners) with a long/short side ratio between 1.2–2.0 (close to the ISO/IEC 7810 card ratio of ~1.586), then computes `pixel_per_cm = pixel_width / 8.56` (8.56 cm being the standard width of a credit card/national ID card), also stabilized with a moving average |

## Requirements

- **Qt 6** (Widgets, Sql, LinguistTools modules) — the build folder targets `Desktop_Qt_6_10_2_MSVC2022_64bit`
- **OpenCV** (built from source locally, placed in the `opencv/` folder)
- **CMake** ≥ 3.16
- **MSVC 2022** (Windows) — the project relies on `cv::CAP_DSHOW` and Windows-style paths throughout, so it is designed to run on Windows
- A webcam

## Build Instructions

1. Open the `CMakeLists.txt` of the folder you want to build (e.g. `GUI_card/CMakeLists.txt`) with Qt Creator
2. Select the `Desktop Qt 6.10.2 MSVC2022 64bit` kit
3. Check/update the `OpenCV_DIR` path in `CMakeLists.txt` to match where OpenCV was actually built on your machine (currently hardcoded to `C:/project_compro/opencv/build`)
4. Configure, then Build as usual
